本文保留实际过程，供期末作业整理使用。内容由 AI 根据操作证据记录；个人体会部分留给学生在使用后补充，不代写虚构经历。

## 2026-11-07 第一阶段：ARIS 部署

### 输入要求

使用 ARIS 构建一篇语义通信方向论文，先复现基线，再探索改进；保留代码、真实结果和过程记录。Python 必须使用 Conda 独立环境，不修改环境变量，大型软件由用户指定位置。

### 遇到的问题与处理

1. 受限执行上下文中 GitHub 连接失败；改用获授权的联网执行方式下载源码，未更换仓库来源。
2. 官方安装器会额外写入用户级仓库指针。为了保持项目局部部署，只在副本中跳过这一步，保留上游原文件。
3. Conda 默认附加插件读取用户缓存时发生权限错误。使用命令级禁用附加插件、classic 求解器和 conda-forge 后成功创建环境，没有改环境变量。
4. Git 仓库由用户账户克隆，受限账户读取时触发所有权检查。使用命令级、单仓库的 safe.directory 参数，未改全局 Git 配置。
5. ARIS 技能示例使用 POSIX 命令。以 PowerShell 包装器和项目解释器的绝对定位调用同一个上游 Python 工具，实际完成了文献入库。

### AI 参与的边界

本阶段 AI 完成部署方式分析、安装操作、环境创建、工具测试及过程记录。没有进行模型训练，没有产生算法实验指标，没有完成新颖性判断，也没有得出方法优于基线的结论。

DeepJSCC 在此仅用于测试真实文献入库。后续将通过 ARIS 正式调研选择基线，避免把部署测试误当复现实验。

### 本阶段可提炼的认识

- “安装成功”需要分层验证：技能文件存在、配套工具可执行、研究流程能完成、GPU 实验可重复，是不同层次。目前已验证前两层。
- AI 工具需要明确的运行约束。将环境、目录和记录要求写入项目入口，能让之后的操作有据可查。
- 部署问题与科学问题应分别记录：权限和平台适配保留在过程日志，研究知识库记录文献与实验事实。
- AI 可以降低准备工具的成本，但基线是否可靠、改进是否有效，仍需要原文核对、对照实验和结果审核。

## 2026-11-07 第二阶段：GPU、选基线与训练准备

用户确认使用 AIRS 项目内目录后，AI 将 PyTorch 的 CUDA 12.8 二进制安装包及依赖下载到 downloads/wheels，临时文件位于 downloads/tmp，离线安装到项目 Conda 环境。没有修改 PATH、CUDA_VISIBLE_DEVICES 等环境变量，也没有安装独立 CUDA Toolkit 或修改显卡驱动。

实际测试不仅检查了 CUDA 是否可用，还运行了卷积、转置卷积和注意力的前后向计算，并检查梯度及 Adam 权重更新。随后新会话按文档重跑一次验证，两次均通过。见 GPU_ENVIRONMENT.md 和 logs/gpu-smoke.json；这是环境测试，不是论文结果。

### ARIS 文献与复现选择

使用 research-lit 工作流，先由官方 arxiv_fetch.py 取得候选元数据，将六篇论文的摘要和作者代码说明冻结到本地证据文件，再由两个只读分片分别提取。覆盖记录列出全部六篇，没有把“有摘要”写成“已精读全文”。已下载并阅读 WITT 全文，检查作者模型与训练入口。

筛选过程发现：候选不只在方法上不同，部署成本也不同。ADJSCC 的作者代码依赖 TensorFlow 和特定平台 compression 组件；SwinJSCC 的官方说明对部分自适应配置给出版本警告。最终先选择有直接作者 PyTorch 组件、低分辨率设置明确且通过本机测试的 WITT 子配置。具体差异记录在 literature/LITERATURE_REVIEW.md。

### 将 AI 建议变为可检查的代码

依照 experiment-plan、experiment-bridge 和 run-experiment 的文档，AI 先写出了数据划分、指标定义和训练预算，再实现入口。训练代码只打开 CIFAR-10 官方训练 split，并保留独立验证集；官方测试 split 不参与模型选择。作者模型结构不改动，也不执行作者入口里的环境变量和固定权重加载语句。

新会话代码审查发现一个实际缺口：仅检查 loss，不能防止反向传播产生异常梯度后仍将训练标记为完成。AI 根据意见补上了更新前的梯度检查、验证输出检查，并保留阶段终点检查点。审查按同系列 provisional 留档，不冒充跨模型科学评审。

信道及指标也作了小型已知真值验证：AWGN 的设定 SNR 与大量样本实测值相符；总体 MSE 换算 PSNR 和逐图 PSNR 平均值分别得到正确结果。这种检查帮助区分“代码可以运行”和“指标含义正确”。

### 当前限制与已发生的问题

- 官方 CIFAR-10 数据源下载较慢，训练要在完整性校验通过后启动；没有用随机生成图片冒充数据集。
- CVPR 2026 官方模板已固定到发布标签；已有 MiKTeX 缺少 times.sty，关闭自动安装后的编译检查失败。已向用户询问处理方式，不擅自安装大型组件到 C 盘。
- WITT 合成输入测试的显存和速度只用于估计预算，不作为模型重建质量的证据。
- 两阶段 2k/6k 更新是本地初始预算。达到论文数值需要后续查看验证收敛情况，不能因为完成了设定更新数就宣称完整复现。

本阶段的个人心得仍由学生在查看产物和参与实验后补充。AI 已记录的是操作事实、发现及纠正。

### 实际数据运行与检查点验证

CIFAR-10 完整下载通过官方 MD5 后，默认执行账户仍报告无法读取。经核对，底层是 Windows 文件权限错误，TorchVision 将其表现为“数据集不存在或损坏”。使用已有文件所属的用户执行上下文后恢复，无需重下数据或更改全局权限。

20步 R000 在真实训练图片上完成。模型权重重新载入后，对相同验证图片和噪声种子重算，三组指标与训练时保存值的最大差为0。这个检查支持训练/存储/评估链路一致，但20步结果仅是运行验证。随后启动正式首轮 R001，两阶段共8000次更新；保留原始日志、配置、源码快照和检查点。

### 小型局部依赖补齐模板

用户批准局部组件后，采用 CTAN 的25个运行包，压缩总计271684字节，保存在本项目。初次补包暴露间接依赖，按 paper-compile 的重复失败规则进行只读二次检查，再一次性补齐。官方 CVPR 模板随后成功生成5页PDF。没有安装完整 TeX 发行版，也没有通过修改环境变量或注册全局路径解决问题。后续正式论文仍需引用、多遍编译和逐页检查。

## 2026-11-07：从子流程转入研究闭环的纠正

用户追问是否真正通过ARIS研究闭环推进。AI明确说明：ARIS技能式部署由当前Codex作为执行AI，既有工作实际只运行了若干子流程，不能称为完整闭环已跑通。随后以research-pipeline为总流程建立真实阶段状态，按用户要求加入先复现基线的前置步骤。此纠正及未完成阶段被保留，没有回填成此前已完成闭环。

真实生成阶段冻结三个分析镜头，三个只读分片返回九个候选，覆盖完整。选取WITT标量SNR门控查表部署做首个低成本pilot。新会话查新评审指出神经网络查表和条件缓存已有先例，要求加入13点整数缓存、非整数SNR和每批SNR只算一次的对照。AI据此修改了协议，保留最初P000准备记录，重新生成P001而没有覆写。

代码评审又指出初版只比较压缩模型与原始模型，不能证明压缩模型保存重载前后一致。修补后每个变体均从原检查点重新编译，与已保存重载模型在配对噪声下对比，最大差都为0，随后才计算真实图片指标。七个变体、固定1000验证图、13个SNR、三次噪声重复均完成。5点线性表文件缩小约30.03%，指定网格最大PSNR损失约0.00907dB，最近邻5点的最坏损失约0.12953dB。这个初步结果支持后续验证，尚不是充分训练、多种子或最终测试结果。计时顺序固定、波动明显，暂不宣称加速。

R002在约20分钟后自动保存完整断点并暂停在15300总步。用户随后因额度不足要求明日继续，AI停止新实验并整理SESSION_HANDOFF.md。后续还需要按ARIS对真实pilot进行critical review、方法细化、正式实验及论文写作；不把一次正向查新意见当成研究闭环完成。
