# ARIS 辅助语义通信研究：全过程记录

本文件把项目中实际发生的工作按研究逻辑串起来，供阅读、核对和撰写个人心得使用。这里记录研究过程与证据，不代写第一人称感受。论文署名与学校按照你的要求保留占位符。

## 1. 这项作业要完成什么

前一份通信领域 survey 已经完成。本次期末作业是另一个任务：利用 AI 研究工具构建一篇包含代码链接和真实实验结果的论文，并记录工具使用过程。课程要求参考 CVPR 2026 的 paper 格式，研究方向选择语义通信。

项目采用 ARIS 的技能式工作流，由 Codex 实际执行。ARIS 提供文献、实验、批判评审、修订、结果核查和写作等阶段的操作说明；执行 AI 负责读材料、写代码和运行工具，新的审稿会话负责检查指定证据。用户决定研究方向、计算预算、环境安装位置和是否公开仓库。

开发从一开始就有明确约束：Python 只使用项目内 Conda 环境；不修改环境变量；不做未经批准的全局安装；大型环境和下载放在 D 盘 AIRS 项目内；训练分段保存。后续还加入五小时额度监测：工作期间检查实际账户额度，剩余约 10% 时整理并停止。

## 2. 为什么选择 WITT 作为基线

第一步不是直接生成一个“新方法”，而是筛选能够实际运行的参考系统。文献筛选覆盖 DeepJSCC、ADJSCC、WITT、SwinJSCC、HJSCC 和 DD-JSCC。筛选关注三个问题：作者是否提供可核查的实现；论文和代码是否有明确的数据、信道和指标；本机资源能否承担首轮训练和对照。

最终选择 WITT 的 CIFAR-10、AWGN、MSE 子配置。WITT 使用 Transformer 进行无线图像传输，并利用信噪比 SNR 调整特征。它有公开作者代码和明确的小图像配置，便于先建立可运行、可解释的实验。后续更复杂的架构仍作为领域背景，没有把摘要里宣称的性能直接当作本地结果。

这项任务可以简化为：图像经过神经编码器形成待传输表示，经过模拟噪声信道，再由神经解码器重建；训练目标是降低重建误差。它属于学习式联合信源信道编码（JSCC）的图像传输研究。当前实验评价的是重建质量，没有把它扩展成卫星实测或下游识别任务。

作者代码固定在提交 `2460db52264ad35d0d7521c9f505fc318134c086`，原始目录保持不改。项目自己编写训练、断点、配置、评估和分析入口，导入作者的模型与信道组件。这样既能保留基线实现，也能明确哪些工作由本项目完成。

## 3. 从部署到真正训练

部署先完成 ARIS 的项目局部安装，再创建 Conda 环境并配置 GPU 版 PyTorch。本机为 RTX 5070 Laptop GPU，约 8 GB 显存。使用的主要版本是 Python 3.11、PyTorch 2.9.1+cu128、torchvision 0.24.1+cu128 和 timm 0.9.16。先通过实际前后向计算检查，再进入训练。

这里遇到过一个容易误判的问题：数据由用户账户创建，受限执行账户读取时出现权限错误，但数据加载器将它表现为“数据集不存在或损坏”。检查后改用已经验证的用户执行上下文，没有重新下载数据或修改全局权限。

数据采用 CIFAR-10 的官方 50,000 张训练图和 10,000 张测试图。训练图按固定随机种子划为 45,000 张训练、5,000 张验证。模型选择与方案调整使用验证集，正式测试集留到方案冻结后使用。

基本训练配置如下：

| 项目 | 实际设置 |
|---|---|
| 图像 | 32×32 RGB，输入缩放到 0–1 |
| 训练增强 | 概率 0.5 的随机水平翻转 |
| 信道 | 模拟复数 AWGN |
| CBR | 1/3，复数信道使用数 / 实数源样本数 |
| batch size / 学习率 | 128 / 0.0001，Adam |
| 训练随机种子 | 42，一条训练轨迹 |
| 第一阶段 | 非自适应前向路径，7 dB，2,000 次更新 |
| 第二阶段 | 同一模型启用自适应路径，从 1、4、7、10、13 dB 均匀抽样 |
| 训练损失 | 裁剪重建图像后，在作者的 0–255 数值尺度计算均方误差 |
| 阶段切换 | 延续已有权重，启用原先绕过的调制模块，重新建立 Adam |
| 选模 | 每 500 次更新，在 1、7、13 dB 验证，按三点平均 MSE 选最优 |

所有模块在模型构造时已经创建。第一阶段绕过的调制模块保留初始化权重，到第二阶段才参与训练；阶段切换时没有临时新增另一组参数。

训练前先做了 20 步真实数据试运行，并检查权重保存重载。随后比较“连续训练 22 步”和“20 步保存后再续训 2 步”，模型、Adam、采样器和随机状态都一致。这一检查为之后按时长分段训练提供了依据。

| 训练段 | 结束总更新数 | 实际状态 |
|---|---:|---|
| R000 | 20 | 真实数据与保存/重载检查 |
| R001 | 8,000 | 完成；后来用作初步方案试验的检查点 |
| R002 | 15,300 | 保存完整断点后暂停 |
| R003 | 22,645 | 从 R002 继续，分段保存后暂停 |

最终选中的模型位于 **21,500 次更新**，而不是最后保存的 22,645 次更新。对 41 次符合规则的历史验证进行了核对，21,500 步模型满足既定选模规则。截止时额外进行的临时验证不参与选模。

这一步完成了有限预算下的作者组件复现。现代依赖、验证划分和训练预算与原论文协议存在差异，尚未建立与原论文曲线的数值一致性或收敛证明。因此，报告没有将“能够训练并取得合理重建结果”写成“已经完整复现原论文性能”。

## 4. 优化想法是怎样产生的

读模型代码后，项目关注到 WITT 的两类计算：一类依赖图像内容，另一类只依赖一个标量 SNR。后者在编码器和解码器中各有 7 个 MLP，共 14 个。每个 MLP 都将一个 SNR 数值映射为 384 维门控向量，再与图像相关的隐藏特征逐元素相乘。

候选生成从三个分析视角形成 9 个方案。除最后选中的方案外，还考虑过在训练中加入 SNR 条件误差，以及分别扰动编码端、解码端的条件信息来定位失配。最终优先选择 **训练后将标量 SNR 门控网络转换为查找表**，原因是干预范围明确，能直接检查质量与存储之间的关系，也不需要为每个候选重新训练一遍大模型。

查表的直观做法是：训练完成后，提前计算若干个 SNR 下的门控向量并保存；运行时，如果当前 SNR 位于两个节点之间，就对两组向量做线性插值。图像相关的网络继续运行，替换的只有这些标量到向量的映射。

例如，13 节点表保存 1、2、…、13 dB 的结果。2 dB 正好是节点，可以直接取值；2.375 dB 则需要用 2 和 3 dB 两个节点插值。只测试整数节点会遗漏插值误差，因此后续必须专门测试非整数 SNR。

每个标量 MLP 的维度为 1→384→384→384，含偏置共 296,448 个参数，14 个合计 **4,150,272 个参数**。13 节点方案保存门控值和节点位置，共 70,070 个 FP32 数值，即 280,280 原始字节。相较于保存这些 MLP 的全部参数，存储代价明显下降。

查表和插值本身已有文献基础。项目查新后将研究定位为具体的部署实证：在 WITT 的这个条件分支上，需要多少节点，完整推理文件能减少多少，以及插值对重建质量有什么实际影响。没有把通用查表思想宣称为首次提出。

## 5. 第一轮试验与评审如何改变方案

初步试验 P001 使用 8,000 步检查点，在固定 1,000 张验证图、13 个 SNR 条件、三次配对噪声下比较七个变体。

| 方案 | 全网格最大有符号 PSNR 损失（dB） | 作用 |
|---|---:|---|
| 原模型 | 0 | 比较基准 |
| 共享 SNR 计算 | 约 0 | 保留原 MLP，只把每批重复计算改为算一次后广播 |
| 3 节点线性表 | 0.093756 | 检查较稀疏节点的质量代价 |
| 5 节点线性表 | 0.009071 | 节点数与质量的折中 |
| 9 节点线性表 | 0.000389 | 检查增加节点的影响 |
| 13 节点线性表 | 0.000258 | 覆盖整数 SNR，并检验非整数条件 |
| 5 节点最近邻表 | 0.129533 | 对照插值规则 |

有两个对照尤其重要。首先，共享 SNR 计算仍保存原 MLP 的参数，帮助区分“少算重复内容”和“真正删除参数”。其次，同样是 5 个节点，线性表和最近邻表文件大小相同，但后者质量损失明显更大，说明节点个数之外，取值规则也会影响结果。

批判评审发现，早期汇总把三节点方案在一个较窄子集上的 0.080834 dB 当成了整体最大损失。按完整 13 点网格重新核查，正确值为 **0.093756 dB**。原始数据没有被改写，修正后的汇总单独保存。

评审还指出只看常见训练 SNR 或整数节点不足以检验查表。方案因此改为：将 13 节点作为主方案；增加更密的非整数验证；保存逐批误差和图片数量；在正式测试之前冻结模型、部署文件和测试条件。方法细化经历了一次要求修改和一次肯定意见，之后才继续验证。

这部分是研究闭环实际发挥作用的地方：评审改变了后续要测什么、怎样保存统计量，以及何时允许进入测试集。

## 6. 后续验证与正式测试

后续实验使用按既定规则选出的 21,500 步检查点。

| 实验 | 数据 | 条件与目的 |
|---|---|---|
| P002：密集验证 | 1,000 张验证图 | 32 个固定 SNR；比较原模型、5 节点和 13 节点；补充半整数及额外分数条件 |
| P003：完整验证 | 全部 5,000 张验证图 | 8 个预选 SNR；比较原模型和 13 节点，检查扩大图片数量后的结果 |
| P004：冻结测试 | 官方 10,000 张测试图 | 相同 8 个预选 SNR；三组新的配对噪声；模型和节点不再调整 |

P002 中，13 节点最大有符号损失约 0.000454 dB，5 节点约 0.015405 dB。P003 中，13 节点约 0.000264 dB。两个验证实验实际通过质量、存储和重载检查门槛后，才生成测试冻结记录并运行 P004。

预设质量容差为最大有符号损失不超过 0.1 dB，存储门槛为完整推理文件至少减少 25%。它们是工程准入条件。实际结果远小于质量容差，但结论依然对应本次数据、模型和测量条件。

配对噪声是指：同一张图、同一 SNR、同一次重复中，两个方案使用对应的信道噪声，尽量减少比较中与方案无关的随机差异。三次噪声重复不等于训练了三个随机种子的模型。

## 7. 最终结果应当怎样理解

完整推理文件的实际大小从 **54,987,545 字节**减到 **38,644,489 字节**，减少 **29.7214%**。保留下来的 223 个非门控张量经 CPU 检查全部相同，推理文件不包含 Adam 等优化器状态。这确保比较的是可部署模型文件，而不是把训练状态误算成优化收益。

P004 的最大有符号 PSNR 下降为 **0.00018648792025736705 dB**，发生在 2.375 dB。论文摘要直接保留六位小数时写成 **0.000186 dB**。最大绝对变化约 0.000337846 dB，发生在 1.5 dB，方向是查表方案的小幅改善。最大下降和最大绝对变化是两个不同统计量。

PSNR 按所有图片、噪声重复的 MSE 汇总后换算，区别于先算每张图片的 PSNR 再取平均。统计区间通过配对的原始 batch 分组重采样得到，并按图片数量处理最后一个较小 batch。区间是固定模型、固定图片批次和所记录噪声下的逐点描述，不能据此推出所有连续 SNR 的统一保证。

从工程角度，这项优化改善的是**模型部署存储**。编码器和解码器仍使用相同的信道模型与 CBR，图像传输的信道使用数没有因查表而减少。

初步计时也没有显示一致加速。在固定顺序的 pilot 中，13 节点与原模型的中位耗时分别为：batch 1 时 40.4 与 36.2 ms，batch 128 时 43.7 与 46.3 ms。一个条件较慢、另一个较快，因此论文保留这些观测，没有宣传稳定的速度提升。

## 8. 写作和核查中又发现了什么

论文以存储收益为主线，介绍基线、查表方法、验证与冻结测试、结果和局限，使用 CVPR 2026 模板。图表由保存的 JSON 生成，没有为了画图重新打开测试集做推理。

核查分为不同职责：实验完整性检查关注数据与评估流程；结果到声明的审查关注证据能支持什么；数字审查逐项比对论文与原始记录；引用审查检查论文是否存在、元数据是否正确，以及引用语境是否得到支持；写作审阅同时检查源码和实际 PDF 页面。

已经发生并修正的问题包括：

- 三节点 pilot 的较窄子集结果被误当成全网格最坏值。
- 摘要中把测试最大损失二次舍入为 0.000187 dB；直接从原始值舍入应为 0.000186 dB。
- 将 32×32 RGB 图像说成 3,072 个“像素”，后来改为 1,024 个 RGB 像素、3,072 个标量通道值。
- 初稿没有把训练损失尺度、两阶段权重延续和门控乘法位置讲清，写作审阅后补上。
- 引文中的作者姓名分词、变音符号和软件标题需要按主来源规范；ARIS 方法说明补引了作者的技术报告。
- 某些较早的审阅只保留了原始回复，完整调用提示词无法恢复，归档时如实标明缺口；后来送审改用固定快照，避免审阅中途修改输入。

所有审阅都保留其来源范围。独立新会话仍与执行 AI 属于同一模型家族，因此项目不把它们称为跨家族评审或正式同行评审。课程稿的实证与写作评价也和顶会原创研究标准分开记录。

## 10. 阅读后可以自己梳理的几个问题

写个人心得前，可以先用自己的话回答：为什么基线要先跑通；为什么不能只测试查表节点；为什么配对噪声不等于多个训练种子；为什么文件变小不能直接推出传输带宽下降或稳定加速；AI 的哪一次修改真正改变了实验，而不只是修改措辞；如果下一步自己推进，最想验证哪一个尚未解决的问题。

这些问题没有预设的个人感受答案。你可以结合自己的理解、疑虑和判断来写，而不是将这份事实记录改写成未经确认的学习经历。
